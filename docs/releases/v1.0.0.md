# v1.0.0 · G2rain（谷雨）平台管理控制台

本版本准备 G2rain（谷雨）开源智能体平台中平台管理控制台微前端应用的首次 GHCR 镜像发布。该组件提供账号、用户、机构、角色权限、资源、应用授权、身份提供方、服务注册和审计等管理页面与交互；后端数据、认证、Token 签发、网关鉴权和业务规则仍分别由 Basis、IAM、Gateway 与领域服务负责。平台整体能力与开放状态以 [g2rain 中央仓库](https://github.com/g2rain/g2rain) 为准。

## 构建、运行与镜像

- 项目版本事实源为 `package.json`，本版为 `1.0.0`；锁文件和 `docs/project.yaml` 同步该版本。
- 需要 Node.js `>=22` 和 npm。`npm ci` 后的 `npm run build` 执行 Vue/TypeScript 类型检查及 Vite 构建；本仓没有独立测试脚本。
- 镜像地址为 `ghcr.io/g2rain/g2rain-manager-app`，复用根目录 Dockerfile 和 build.sh；构建阶段是 Node 22 Alpine，运行时是 OpenResty Alpine，入口 `/docker-entrypoint.sh`，声明端口 `8080`（默认实际监听 `80`，部署应显式设置 `SERVER_PORT=8080`）。
- 版本 tag `v1.0.0` 发布 `:1.0.0` 和 `:sha-<完整提交 SHA>`，不发布 `latest`。OCI 元数据包括 title、source、url、version、revision 和 `Apache-2.0` 许可证。

## 镜像内容与安全边界

最终镜像包含 Vite 静态产物、OpenResty/Nginx 模板、Lua 签名脚本和离线 luaossl 源包编译得到的运行库。`.env.production` 进入构建上下文，是公开的构建期配置；其余 `.env*` 与 `lua/keys/` 被排除。密钥路径不会复制进镜像，但容器创建了 `/usr/local/openresty/nginx/lua/keys` 供生产 Secret/只读 Volume 注入。

维护者仍须在每次发布前检查 Git 已跟踪配置和构建上下文，确认不存在默认 Token、私有地址或真实凭据。Docker 忽略规则不改变已跟踪文件的公开性。私钥、IAM 公钥与 Key ID 只能经部署 Secret/Volume 注入；`VITE_*` 和 `env-config.js` 对浏览器用户可见，不能承载密钥。

## 发布顺序与权限

按 `feature/* → develop → main`，先合入并验证本说明、版本与工作流，再在该 `main` 提交创建并推送 `v1.0.0`。工作流校验 tag 格式、`origin/main` 历史、同名非空发布说明及 npm 版本，之后执行 `npm ci`、`npm run build`、容器构建和两个 GHCR 标签推送。它使用 `GITHUB_TOKEN` 的 `contents: read` 与 `packages: write`，不创建 GitHub Release、不部署，也不更新 `latest`。

首次成功发布后，需要匿名拉取时在 GitHub Packages 的 **Package settings → Change visibility → Public** 设置公开；若组织策略禁止，请联系管理员。若已有包推送返回 `denied`，先在 **Package settings → Actions access** 授予本仓库 Actions 写权限，并检查组织 Packages 策略。

## 验证状态与限制

本次发布准备已完成 `npm ci` 与 `npm run build`，并完成 JSON/YAML、版本一致性和 Docker 上下文规则检查。构建通过不覆盖单元/E2E（仓库未定义脚本）。Docker 引擎在此环境未启动，因此容器实际构建、运行时 Lua/IAM/Gateway 联调、GHCR 推送、匿名拉取、在线演示和目标环境部署验收仍需以实际执行结果另行记录，不能由工作流定义或本地前端构建推定。已知构建/运行偏差见[架构偏差](../architecture/deviations.md)。本仓按 [Apache License 2.0](../../LICENSE) 开源。
